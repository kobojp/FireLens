# FireLens

**最新已發布 Release：v1.11.0（2026-11-14，GitHub Actions Windows 正式版）**。包含大圖預覽、重複掃描引導、貼圖效能改善、照片槽位標籤管理及查詢頁狀態保留。下載繁體中文 Windows 安裝版、免安裝版、SHA256 校驗檔與 Ed25519 已簽署的自動更新清單：<https://github.com/kobojp/FireLens/releases/tag/v1.11.0>。正式 Release 五項資產與內建 Ed25519 公鑰驗章均通過；真實 Google Drive／WebView2 與現場影像仍待實機驗收。

FireLens 是一套以 Windows 桌面環境為主的消防設備照片管理工具，協助整理滅火器、放置盒與燈具更換照片，並搭配 Excel／文字清冊進行核對、補拍與命名整理。

## 主要功能

- 依「類別 → 年份 → 月份/批次 → 棟別 → 編號」瀏覽照片資料樹
- 快速新增月份、棟別與設備編號資料夾
- 拖放照片並依槽位自動命名
- 同一設備的照片可在槽位間拖曳移動／交換，先預覽確認後安全重新命名，並保留本機復原紀錄（歷史 Release v1.8.0 已發布，仍待 Windows 實機驗收）
- 滅火器槽位：`編號`、`藥劑`、`完成`
- 放置盒／燈具槽位：`前`、`中`、`後`
- Excel／文字清冊核對與補拍清單
- 清冊核對只列出匯入清冊內的設備，其他照片資料夾不混入缺失、統計與 CSV／Excel 匯出
- 清冊核對結果可一鍵匯出缺失 CSV／Excel（桌面版直接儲存至下載資料夾並顯示檔案位置）
- 照片牆設備資料夾安全更名，原位修改資料夾名稱而不變更照片內容
- 設備異常單選標記（瓶身超過10年、無法辨識、壓力錶故障等）、自訂異常分類與獨立「異常統計」分頁
- 髒檔名、近似編號、重複照片與異體字檢查
- 批次改名預覽、執行與還原紀錄
- SQLite 本機索引、縮圖快取與離線工作區
- Windows pywebview / WebView2 桌面介面
- PyInstaller x64 打包

## Google Drive 限制存取更換資料（OAuth 唯讀／編輯）

使用者已把目標 Google Drive 資料夾設為「限制存取」。上方導覽列「設定」右側的「查看滅火器資料」獨立頁籤，改用 **FireLens Desktop OAuth**：
1. 在 Google Cloud 專案啟用 **Google Drive API**、**Google Sheets API**；設定 OAuth 同意畫面的「外部／測試」、加入使用者自己的 Google 帳號為測試使用者。
2. 在 Google Auth Platform **Data Access / 資料存取**設定 `https://www.googleapis.com/auth/drive.metadata.readonly` 和 `https://www.googleapis.com/auth/spreadsheets.readonly`。前者屬 restricted scope，後者為 sensitive scope，未來公開給其他人使用前需要評估驗證限制。因需直接列出已共用私人資料夾的所有 Sheet，目前不採無法列出所有檔案的 `drive.file` 權限。
3. FireLens 內點「使用 Google 帳號登入」，系統瀏覽器會顯示 Google 授權頁；完成後回到 FireLens，清單會自動載入，直接選試算表、工作表，以 React 表格瀏覽（每頁最多 100 列、30 欄，預設唯讀）。每次進入此頁以及完成 Google 登入時均會自動取得清單；「重新整理」保留作為手動重試。自動刷新不清除目前所選試算表、工作表、頁面或未儲存編輯草稿。
4. 只受邀帳號能讀取私人資料。可隨時按「登出 Google」清除本機加密 Token；網路正常時會嘗試遠端撤銷授權。使用者密碼、Token 和內容均不放 GitHub。

### Google Sheets 整欄與多格複製（M17-F）

在「查看滅火器資料」選擇試算表和工作表後，會顯示 A～AD 欄標頭及「整欄複製／多格選取」工具列：

1. **整欄複製**：點選 B 欄標頭可選取整個設備編號欄，勾選是否「包含第 1 列標題」，再按「複製所選範圍」或 Ctrl+C。程式透過已授權的 Google Sheets API 分批取得資料，不受畫面目前只顯示 100 列的限制；最後連續空白列會略過，但中間空白列完整保留。
2. **連續多格複製**：在唯讀模式點選第一格，再按 Shift 點擊另一格擴大範圍；編輯模式可按 Ctrl 或 Shift 點擊來選取（普通點擊仍保留單格編輯）。按 Ctrl+C 或工具列複製按鈕，資料以 TSV（Tab 分欄、換行分列）寫入 Windows 剪貼簿，供 Excel、Google Sheets 或 FireLens 清冊輸入框貼上。
3. **複製錯誤**：剪貼簿不允許或 Google 資料取得不完整時不顯示成功；若資料完整但剪貼簿拒絕寫入，可按「再次複製」。可在載入時按「取消複製」，不會把不完整資料放進剪貼簿。

**安全／效能上限**：單次最多 20,000 列或 100,000 格，Google API 每批最多 200 列；超限明確提示縮小範圍。複製只讀 Google 資料，不需要編輯權限、不更改任何雲端試算表。**整欄貼上與批次寫入尚未實作，需另行討論驗收與衝突防護。** 真正 Google API 複製與 Windows WebView2 Ctrl+C 互動仍待使用者在新版實機驗收。

### 試算表「唯讀／編輯」模式

登入後預設唯讀。使用者主動切換「編輯」時，才會開啟系統瀏覽器，重新授權包含 Google Sheets 寫入的完整 scopes（Sheets spreadsheets）；Google Cloud 同意畫面 Data Access 須新增寫入 scope。Google 官方說明 Desktop app 不支援 incremental authorization，因此不是靜默增加權限，應在瀏覽器完成完整授權。既有唯讀憑證於取消或授權失敗時保持有效。

真正能不能編輯仍由 Google Drive 分享 ACL 決定：只有被授予「編輯者」的帳號才能儲存；「檢視者」即使已獲得 OAuth 寫入 scope 也不能修改。

**操作說明：** FireLens 編輯模式點一下任一虛線儲存格，會立即在畫面中央開啟文字編輯視窗，按「儲存變更」後還會顯示第二次確認。若想大量貼上、修改格式或公式，選取試算表後，點 **「使用 Google 試算表開啟」**，FireLens 會在 Windows 預設瀏覽器打開 Google Sheets 原生編輯器（有選工作表會一併選擇分頁）。Google 由自己的登入 Cookie 與試算表分享 ACL 決定可否編輯；FireLens 不把 OAuth Token 放進網址。

**為什麼不是直接 iframe 嵌入？** Google 官方的「發布到網路 → 嵌入」是檢視功能，不是可互動編輯器，而且可能使限制存取的更換紀錄對外發布。Google 官方也限制在內嵌 WebView 中登入 OAuth；因此不為了嵌入強制公開資料、跳過 frame 限制或繞過 Google 驗證。原生瀏覽器是完整編輯最可靠的替代方式。

目前採用安全單格修改：在編輯模式點選儲存格，輸入草稿，按「儲存變更」看原值／新值確認，FireLens 先向 Google 重新讀取確認原值未變；衝突即拒絕覆寫，成功時採 RAW 文字模式儲存（等號開頭文字不會變成公式）。不支援修改公式、格式或合併儲存格。Google Sheets API values.update 沒有原子 compare-and-swap，若其他人同一瞬間修改仍可能競爭；重要工作紀錄請保留 Google 試算表版本歷史。

FireLens 使用 OAuth **Desktop Client ID**（公開識別碼），不需要將 Client Secret 提交給專案。採 Windows DPAPI 將 Token 加密到使用者的 LocalAppData。舊公開 API Key、自動公開清單與 iframe 模式均已停用。Google OAuth 測試模式的授權可能在數天後需要重新登入。

### Google OAuth Client Secret 本機設定（推薦）

在 FireLens 上方「設定 → Google OAuth 設定」，可查看唯讀 Desktop Client ID，將 Google Cloud Console → Google Auth Platform → 用戶端 → FireLens Desktop 的 Client Secret 貼到密碼欄，按「加密儲存」。已設定時僅顯示狀態，不顯示原文，可覆寫或清除。後續 Google 登入與 Token 續期優先讀取設定頁的加密值，不需要使用 PowerShell。

Windows DPAPI 將 Client Secret 以目前使用者身分加密到 LocalAppData 獨立檔案，不寫入 SQLite、前端 bundle、Google Drive 或 Git。Client Secret 在桌面程式不是真正安全的身分驗證機密，Google OAuth 仍依賴 PKCE／state 與 Google 權限。

舊的使用者環境變數 FIRELENS_GOOGLE_CLIENT_SECRET 仍可作為備用。兩者都未設定則保留 PKCE-only。Google 官方 Desktop OAuth 文件列 Client Secret 為選填，但部分實際 Desktop + PKCE 環境曾回報 invalid_request: client_secret is missing。

### Google 登入失敗排查

新版 FireLens 對 OAuth 授權碼交換的 Google HTTP 400 錯誤，會以**白名單錯誤代碼**顯示具體原因，且不呈現授權碼、Token、Google 私人回應或 `error_description`。如 `invalid_grant` 先重新登入（可能與授權碼逾時、重複兌換、PKCE 或回呼不一致有關），`invalid_client` 檢查 Desktop OAuth Client ID，`invalid_request` 檢查授權碼交換參數，`invalid_scope` 檢查 Google Cloud 資料存取權限。回呼瀏覽器的錯誤畫面也會顯示不含敏感資訊的原因，請只提供安全錯誤代碼或截圖，**不要提供瀏覽器地址列的完整授權碼與 state**。

**狀態：** v1.8.0 已正式發布至 GitHub Releases；OAuth／API 已通過合成測試，**尚未**經使用者 Windows 真實 Google 帳號與私人資料夾完整驗收，不得將發版視為該項實機驗收通過。

## 照片品質大圖預覽與新手掃描導覽（v1.11.0 MINOR 開發版）

在「照片品質檢查 → 圖片品質與缺槽位」及「重複圖片」清單，點任何縮圖會開啟接近「照片瀏覽」的**大型深色預覽視窗**，上方可調圖片縮放 50%～400%，按「上一張／下一張」連續檢視目前已載入清單，亦可按 ←／→ 鍵切換、Esc 關閉；放大後可捲動畫面查看滅火器瓶身小字。底部保留設備、槽位、檔名及來源路徑。換清單篩選或頁碼時，舊預覽會安全關閉。

第一次貼圖／LINE Ctrl+V／拖放圖片時，若已有大量舊照片**尚未建立 SHA-256 重複指紋**，系統現在回覆明確狀態「照片尚未儲存」，附「前往重複掃描」按鈕。點擊後將自動進入**原照片根目錄**的「照片品質檢查 → 重複圖片」分頁，上方提供像遊戲任務的 1／2／3 步提示，並高亮「開始重複掃描（增量模式）」按鈕。此步驟**仍由你親自按下**；掃描完成才能點「返回照片牆重新貼上」。原先的待貼圖片暫存在本次操作的記憶體中，無須回 LINE 再次複製；返回後點「重新嘗試貼上」，若真有重複會再顯示原有的來源比對與二次確認。掃描失敗／取消時可修正後重試或關閉任務引導。從未要求掃描的正常貼圖不出現這些引導，也不會強制下載 Google Drive 未同步原圖。

## 設定頁照片槽位標籤化管理（M19-I）

「設定 → 介面與快取 → 各類別照片槽位（標籤管理）」不再需要手動輸入「前、 中、 後」這種頓號分隔字串；每個設備類別（滅火器／放置盒／燈具／水帶或其他動態資料夾類別）有**獨立卡片**：

- **基本照片槽位**：現有槽位以藍色 Chip 呈現，可點「＋新增槽位」、鉛筆改名、× 移除、拖曳或左右箭頭排序；這些基本槽位仍參與缺照判定。
- **槽位顯示順序**：綠色 Chip 只允許調整既有基本槽位順序，不接受憑空新增另一個槽位；下方可預覽照片牆排序。
- **自訂槽位（選填）**：紫色 Chip 可增減、改名及排序，原本就不納入缺照判定，適合「側面」「壓力錶」「補充」等補拍照片。

每個類別有自己的「儲存槽位設定」和「還原這個類別」，未儲存會有明顯提示。新增或改名時會檢查空白、重複、超過 20 字、Windows 檔名禁用字元、檔名同義詞衝突；改名／刪除舊槽位須先確認可能讓照片顯示在「未對應照片」。**不會刪除或重新命名照片原檔**。系統以一次 API／SQLite 交易儲存該類別基本槽位、顯示順序及選填槽位，失敗不會部分寫入；保留舊版 API 與既有儲存格式相容。儲存其中一類別，也不會清空其他類別未儲存的草稿。完整自動化回歸與 Windows 打包屬開發驗證，實際 WebView2／Google Drive 操作仍需人工驗收。

## 照片貼上效能優化（v1.11.0 MINOR 開發版）

已完成照片根目錄索引後，FireLens 貼上圖片會直接在 SQLite 的 SHA-256 指紋索引查詢相同內容，只檢查命中的候選照片，不會為每次貼上重新巡查整個 Google Drive 或根目錄。第一次或照片有新增／變動而尚未建立指紋時，可自動補查**最多 8 張／合計 8 MiB**的本機安全檔案；較大或無法同步的情況會明確要求到「照片品質檢查 → 重複圖片」執行手動增量／完整掃描，保留原有跨設備相同照片提示和強制儲存二次確認。另會在照片安全存入後立即更新指紋，照片牆先顯示結果，資料樹與離線佇列在背景刷新；上一個根目錄的過期請求不會覆寫目前畫面。

桌面「貼上照片」按鈕繼續使用**無損 PNG**，但改用較快的壓縮參數；首次預覽後會顯示剪貼簿擷取毫秒數，照片寫入完成後顯示後端的「處理／重複查詢／寫入驗證／索引」階段耗時。這些數據有助於找出慢點，但不是整個 Google Drive 同步耗時，也不代表已在真實 WebView2 和 LINE 剪貼簿測得 1 秒內。資料庫 schema 會安全升級到 13，只增加查詢索引，不改動原始照片與檔名。

## 返回照片牆後保留查詢（v1.11.0 MINOR 開發版）

開啟「照片品質檢查」（含重複圖片）或「清冊核對」後，會在**同一次 FireLens 執行期間**保留目前選擇的根目錄、搜尋條件、過濾、頁碼、已載入查詢結果與清冊草稿。點「前往照片牆」查看設備，或暫時切換到其他主功能標籤，返回後不必重新開始查詢。從未打開過的頁面不提前載入；隱藏頁面無法被鍵盤聚焦。真正關閉 FireLens 再啟動不保證恢復暫存工作狀態。Windows WebView2 的操作還需實機驗收。

## 根目錄自動發現與重複照片提醒（v1.10.0 正式 Release）

FireLens 不再只識別「滅火器／放置盒／燈具」三種資料夾。把「水帶」等新目錄放在已設定的照片根目錄第一層，重新掃描後會顯示獨立的資料樹類別；內部有照片的子資料夾會被索引，沒有固定年／月結構時顯示「(未分類)」。新類別預設「前／中／後」三個槽位，既有單槽「照片」類別在新版資料庫升級後會轉為三槽（重新掃描後照片按檔名歸位）；滅火器原本預設編號／藥劑／完成，放置盒、燈具預設前／中／後。所有類別均可到「設定 → 介面與快取 → 各類別照片槽位（可自訂）」編輯以頓號分隔的槽位名稱，支援新增、刪除、改名、排序並獨立儲存。改名／移除會先顯示影響確認，不能對應新名稱的舊檔名照片保留在「未對應照片」，不會修改原圖或檔名。設定頁的「介面與快取 → 排除根目錄資料夾」可新增及移除不想列入的第一層目錄名稱，儲存後重新掃描生效。`FireLens-共享異常資料` 及 Windows 系統資料夾永遠不會被照片掃描收錄。排除不刪除實體資料。

**跨設備重複圖片偵測（M19-C）**：從「照片品質檢查」切換「重複圖片」，選照片根目錄，按「開始重複掃描」。預設為手動增量模式，只重算新增／變動照片；完整模式會重新計算所有安全本機照片的 SHA-256。新資料庫先建立持久化指紋索引，之後沿用未變動快取。結果按完整相同 SHA-256 分組，列出不同類別、月份、棟別、設備編號、槽位、檔案與來源路徑；可看原圖、前往照片牆，並匯出全範圍 CSV／Excel。從 Windows 檔案總管直接把「三-07-25」的照片複製到「水帶／F-19-13」，只要在 FireLens 執行手動掃描，同內容照片也會被找出。

從「加入照片」、拖放或 Ctrl+V／LINE 匯入新圖時，會先針對**相同照片根目錄內所有已索引設備**比對「最終準備寫入的圖片位元組」。跨設備或同設備命中時先回傳 HTTP 409，再顯示來源／目的圖片並排預覽、來源設備與完整相對路徑，可選取消、查看原照片或明確「仍要儲存」另一份，絕不覆蓋舊圖。小型索引可在匯入時增量補建；大型根目錄尚未建好指紋時會要求先到「照片品質檢查 → 重複圖片」進行手動掃描。**只檢查 SHA-256 完全相同，不等於視覺相似辨識。** 未下載的 Google Drive 佔位檔不會強制下載；畫面會標示「待檢查／未檢查」，不能把這類照片宣稱無重複。離線佇列重新連線遇到重複時保留錯誤與待處理項目，不自動強制重複寫入。

## 資料樹的展開／收合與新增資料夾

FireLens 左側「資料樹」可直接點擊年份、月份／批次、棟別的箭頭或標題展開／收合；每個照片根目錄的展開選擇獨立保存於本次程式執行期間。點選左側「＋」或右鍵「新增…」以及上方快速新增後，成功建立資料夾時**只會展開新資料夾的父路徑並定位／高亮新節點**，不會把其他年份或月份全數展開。新增取消或失敗後仍保留原本展開狀態。輸入搜尋字串時暫時展開符合結果的節點，清除搜尋後回復原本的手動展開選擇。

## 照片品質檢查（歷史 M18，v1.9.0 Release）

在頂部主標籤「整理工具」右側點「照片品質檢查」。選根目錄、設備類別、月份批次、棟別與編號；可調縮圖大小、品質問題篩選、人工覆核與排序。預設顯示異常設備，一設備一卡片；滅火器為編號／藥劑／完成，放置盒／燈具為前／中／後，舊制放置盒另顯示「舊制照片」。可查看原圖、人工標記已確認／誤判／待補拍／拍攝內容錯誤及返回照片牆。缺照片與無法辨識照片用途會另外列出，與原設備異常單選紀錄分開。

掃描預設「手動＋增量」：按「開始掃描」先更新照片索引，再只分析上次以來新增或大小／修改時間有變的照片。選「完整重新掃描」後按開始會要求確認，重新分析選定範圍全部照片，不沿用品質分數。開啟頁面與按「重新整理清單」都不會自動品質掃描。顯示掃描中、已分析、快取、跳過、疑似異常等進度並可取消。變更「模糊偵測靈敏度」先儲存，舊結果會標示待重算，需要再次手動開始掃描。

影像分析以 Pillow 讀取原圖的記憶體工作副本，不修改來源。主要偵測疑似失焦、過暗／過曝、低解析度、解碼失敗與低紋理無法判定；只是人工複查候選，不能取代對拍錯設備、實物規格的人工判斷，也不保證所有晃動能辨識。Google Drive 佔位檔不強制下載。異常清單可匯出 CSV／Excel（含設備、槽位、原因、分數與安全相對路徑，不含圖片）。

品質資料由獨立 SQLite schema 10 的 photo_quality 和 photo_quality_setting 表保存，保留舊照片與設備異常。升級沿用資料庫備份機制；請勿把本機 SQLite 放到 Google Drive 讓多台電腦同時寫入。實際 Windows WebView2 操作、縮放與真實照片門檻仍需人工驗收。

## 照片卡片操作按鈕的自適應排列

照片槽位牆的「編號／藥劑／完成」（或放置盒、燈具「前／中／後」）會依照片面板寬度自動顯示 3、2 或 1 欄。每張照片的「換圖、重新命名、移動／交換、刪除」等按鈕會依卡片寬度自動排列，窄卡片採兩欄，極窄卡片改成單欄，不會把刪除藏到右側。原本的操作與確認流程完全不變；Windows DPI 及實際 WebView2 版面仍需實機確認。

## Google Drive 多人異常紀錄同步與本機備份（M17-J）

### Windows 同步資料夾的 desktop.ini

Google Drive 電腦版或 Windows 檔案總管可能在 FireLens-共享異常資料/events 目錄建立 desktop.ini。此檔為 Windows 資料夾設定，不是 FireLens 同步事件。FireLens 會自動略過此已知檔案，不需也不應手動刪除它；真正未知的檔案或損壞 JSON 事件仍會停止匯入，以保護本機資料。



此功能透過已安裝的 Google Drive 電腦版同步資料夾，不使用 Google Sheets OAuth，也不直接共用 SQLite。先確保兩台 Windows 都能存取同一個 Google Drive 共用照片根目錄，然後各自在「異常統計」選擇根目錄，點「啟用此根目錄同步」並確認。程式只會新增獨立 FireLens-共享異常資料/events，原本照片與清冊不修改。

首次啟用會保存原本單選異常標記和自訂異常分類為獨立事件，並備份本機資料。新異常、清除異常、分類修改或設備資料夾更名均建立具因果關係的 UUID JSON 事件，每台電腦有獨立 device_id、SHA256 校驗。開機時及約每兩分鐘檢查本機 Google Drive 同步目錄，也可以按「立即同步」。顯示「本機已讀取」不代表 Google Drive 伺服器已確認上傳，仍須查看 Google Drive 電腦版同步圖示。

不同設備的更新會合併；同設備或同分類並行修改出現不同值時，畫面列出衝突事件，使用者必須明確選擇一個版本才會套用。雲端事件誤刪、檔案損壞、版本退回、離線或尚未完成同步時，不會清空本機異常資料，也不會直接覆蓋共享事件。人工按「修復雲端誤刪事件」才會將已驗證封存檔補回共用目錄。

本機歷史備份放在 LOCALAPPDATA/FireLens/backups/shared-issues（若設定 FIRELENS_DATA_DIR 則使用其 backups 子目錄），不在軟體安裝目錄。統計頁可預覽備份筆數並選擇「復原本機」；復原前再備份，完成後暫停同步，必須人工確認才可繼續。共享事件硬上限 10000 個、單事件 32KiB，不自動刪除事件歷史；超量時停止同步而不是截斷資料。

此版本已用合成雙電腦 SQLite＋共用目錄測試，真實兩台 Windows 和 Google Drive 的授權、上傳延遲與誤刪回復仍需使用者實機驗收。

## 清冊核對：滅火器／放置盒／燈具獨立搜尋

「清冊核對 → 清冊與核對範圍」提供照片根目錄、設備類別／搜尋資料夾（滅火器／放置盒／燈具）、清冊版本，以及**只列出該根目錄下該類別的月份／批次**的下拉選單。每次切換類別或根目錄時，月份自動回到「全部月份／批次」；不會把滅火器 10 月的條件拿到放置盒 11 月搜尋。選單沒有月份時仍可使用「全部月份／批次」。清冊版本由使用者選擇，不會擅自修改已存在的清冊。

按「開始核對」後結果上方會標明根目錄、設備類別、月份與清冊版本，系統只對**所選類別、所選清冊列出的設備**核對。滅火器仍用「編號／藥劑／完成」，放置盒與燈具用「前／中／後」；相同編號出現在不同類別時不互相配對。CSV／Excel 缺失匯出沿用這個核對結果，切換根目錄／類別／清冊／月份會清空舊結果及開檔操作，且不接受舊請求後到的資料。跨月份出現同類別同編號可能標記為重複，不會隨機選一個資料夾。

此功能只讀取現有照片索引和清冊；真正 Windows UI 點擊操作尚待實機驗收。清冊自動綁定類別與分類專用編號格式目前未定案，不強制修改既有清冊資料。

## 異常統計 CSV／Excel 匯出

在「異常統計」可依根目錄、異常分類卡片、棟別樓層與設備編號／來源關鍵字篩選。匯出 CSV／Excel 只輸出目前畫面符合條件的設備，先顯示筆數，0 筆時不允許匯出。成功後顯示檔名、大小、路徑、「開啟檔案」與「開啟所在資料夾」。

CSV 為 UTF-8 BOM；Excel 為 XLSX，欄位依序為設備編號、異常分類、棟別樓層、年份、月份／批次、根目錄、標記時間、照片相對路徑。輸出包含公式注入防護，並且不輸出 UI 的「查看照片」按鈕。檔案儲存在 Downloads/FireLens，以時間戳與隨機檔名避免覆蓋。

匯出期間會鎖定篩選，並由後端檢查預期筆數；若資料變更就回傳 409，不建立過時檔案。改變篩選或重新整理後舊的開檔按鈕取消。現有資料屬本機已整理的異常統計，Google Drive 多人異常同步仍待後續開發；此匯出不代表所有電腦即時資料。Windows 真實開檔與 Explorer 操作仍待使用者實機驗收。

## 清冊核對

清冊核對只把「完整設備編號」當成必要主鍵；「棟別樓層」是方便閱讀、分組與篩選的選填資訊，不影響是否能找到照片。最簡單的文字清冊可以直接一行一個編號：

```text
動-01-15
致-B1-67
中-B2-05
```

也可以直接從 Excel 複製兩欄貼上：

```text
致德樓8F	致-08-19
致德樓B1F	致-B1-67
中正樓B2F	中-B2-05
```

Excel 支援有標題或無標題的一欄／兩欄資料；有標題時可使用「棟別樓層／區段」與「設備編號／編號／滅火器編號」，其餘多餘欄位會忽略。文字與 Excel 都會先顯示解析預覽、重複編號與無法辨識資料，再由使用者確認儲存。舊清冊既有的型式規格、上次更換日與原始資料仍保留相容，但新核對流程不再要求這些欄位。

Windows 桌面版「匯出缺失 CSV／Excel」會直接在使用者的 `Downloads/FireLens` 資料夾建立不覆寫的檔案，並在頁面顯示完整路徑與儲存結果；若無寫入權限會明確顯示失敗原因。匯出的是**整份清冊核對結果中的缺失項目**，不受目前畫面篩選影響；瀏覽器用的 GET 下載路由仍保留。測試時可使用 `FIRELENS_EXPORT_DIR` 指定隔離的暫存匯出目錄。

照片瀏覽的設備編號右側提供「更改名稱」，更名只影響當前設備的實體資料夾及索引，不會修改照片內容或舊清冊編號；離線、掃描中、雲端未下載照片及同名衝突會阻擋操作。「設備異常」則只能為每台設備選**一項或無異常**，分類可在「統計」頁建立、更名、排序或停用，重新掃描不會清除紀錄。統計清單可回到對應設備照片牆，不提供「已改善」流程。

### 照片品質檢查：M18-D 異常清單整合（歷史 v1.9.0 Release）

在「整理工具」右側獨立的「照片品質檢查」中，除了模糊、曝光、缺照片、未對應用途，也能依整理工具既有規則看到**滅火器疑似錯名的建議檔名**（例如 `編輯.jpg → 編號.jpg`），以及**同一合法槽位有多張照片**的人工核對提示。兩種情況可獨立篩選並納入 CSV／Excel 問題欄；計數為問題線索數，並不等同不同照片數。建議名稱只顯示，不會自動 rename；同槽多圖也不代表必須刪除。舊制放置盒不套用新制槽位的多圖判斷。

此頁繼續維持**手動啟動**圖片品質掃描，預設增量；瀏覽與匯出僅查詢 SQLite 索引，不重新分析原圖。`5P 二氧化碳滅火器`、`壓力錶壞`、`新增5P 二氧化碳(含放置盒)` 特例批次與清冊核對共用判斷：照片卡片標示「特例資料夾」，不依一般三槽位規則誤報缺照／未對應用途／同槽多圖；特例照片仍可手動掃描模糊及曝光。新增「特例資料夾」與「名稱異體字」篩選；棟別或設備編號的異體字（例如 `致徳樓 → 致德樓`）只顯示人工修正建議並可匯出，不自動修改資料夾。特例分類本身不視為品質不良。真實 Windows WebView2 操作與現場影像門檻仍需後續驗收。

### Windows／瀏覽器剪貼簿圖片貼上（歷史 v1.9.0 Release）

Windows `FireLens.exe` 的「貼上照片」按鈕改由 pywebview 原生橋接讀取 Windows 剪貼簿圖片（PNG 工作副本），**不需要瀏覽器 `clipboard-read` 授權視窗**。只在使用者按貼上時讀取；接受圖片、最多 100 MB／5000 萬像素，沒有圖片或只有複製檔案路徑時會提示，不會擅自匯入或儲存。取得圖片後仍顯示原有的置中預覽／確認視窗。

一般瀏覽器版的 Ctrl+V 維持 `paste` 事件讀取圖片，不需瀏覽器讀取剪貼簿權限；點「貼上照片」改顯示 FireLens **置中**操作引導，請從 LINE 複製圖片再按 Ctrl+V，不再從視窗取得焦點時觸發剪貼簿權限。無法以 CSS 置中或修改瀏覽器原生權限提示，因此從來源避免不必要的提示。Windows 原生貼上須以安裝／portable EXE 測試，不能用普通瀏覽器模式代表實機結果。

### 照片瀏覽：資料樹獨立捲動（歷史 v1.9.0 Release）

左側資料樹展開大量設備時，左側「資料樹／筆數」與搜尋輸入固定在頂部；下方設備清單獨立捲動，不再推動整個 FireLens 視窗。右側照片槽位牆與資訊欄各自捲動；選擇其他設備會讓照片工作區回到頂部，方便立刻查看新照片，但左側搜尋、展開狀態與捲動位置不變。限「照片瀏覽」主頁，其他分頁仍正常捲動。Windows 125%／150% 視覺與實際拖曳、點擊驗收仍需實機確認。

### 照片品質檢查：匯出與掃描進度（歷史 v1.9.0 Release）

照片品質清單的「匯出 CSV／匯出 Excel」不再依賴 pywebview/WebView2 原生附件下載視窗，而是透過 POST `/api/quality/{root_id}/export/save` 使用與其他 FireLens 頁面相同的本機安全匯出登錄機制，將符合目前篩選條件的**所有設備**（不受畫面每頁 40 台限制）存入 `%USERPROFILE%/Downloads/FireLens`（或 `FIRELENS_EXPORT_DIR` 指定位置）。Windows 桌面版按鈕顯示處理狀態、成功檔名與路徑或失敗訊息，並提供「開啟檔案／開啟所在資料夾」；使用一般瀏覽器開啟本機服務時改透過既有 GET API 以 Blob 啟動瀏覽器正常下載，避免儲存在另一個無法存取的伺服器位置。CSV 使用 UTF-8 BOM，Excel 使用 XLSX，兩種輸出都保護儲存格避免公式注入；原始圖片不包含在匯出檔。

品質掃描有可讀的大字狀態、百分比進度條、已完成／總張數、分析／沿用／跳過／疑似問題數及估計剩餘時間。索引階段或樣本不足顯示「計算中」，開始分析並累積有效耗時後才估算，完成／取消後不再倒數。設備總數、異常設備及問題線索改為獨立統計卡片；匯出按鈕與「前往照片牆」按鈕具明確視覺層次及深色模式樣式。

## Windows 安裝

FireLens v1.5.0 起支援完整繁體中文 Inno Setup 安裝精靈 `FireLens-<版本>-setup.exe`。繁體中文語言資源隨 repository 一起版本控制，不依賴開發機另外安裝語言檔。預設採每使用者安裝，不需要系統管理員權限，路徑為 `%LOCALAPPDATA%\\Programs\\FireLens`；安裝精靈可變更目的地、建立開始功能表捷徑，桌面捷徑為可選。

正式安裝版資料庫位於 `{安裝路徑}\\data\\firelens.sqlite3`。若舊版資料庫仍位於 `%LOCALAPPDATA%\\FireLens\\firelens.sqlite3`，且新安裝位置尚無資料庫，首次啟動會以 SQLite snapshot 安全複製並通過 `PRAGMA quick_check` 後才使用新位置；舊資料庫不會自動刪除。測試與更新器 self-test 使用 `FIRELENS_DATA_DIR` 時仍完全隔離，不會碰正式資料。

從歷史 v1.4.0 單一 EXE 使用內建線上更新升到 v1.5.0 時，更新器仍可照原流程安全替換 raw EXE；因為舊版沒有安裝精靈標記，更新後會先繼續使用 `%LOCALAPPDATA%\\FireLens\\firelens.sqlite3`，不會把目前 EXE 所在的下載／桌面資料夾誤認為正式安裝位置。之後執行 v1.5.0 setup 完成正式安裝時，才會把舊 DB 安全搬遷到 `{安裝路徑}\\data`。

## 資料安全

FireLens 將照片磁碟內容視為真相來源；掃描功能只建立索引，不應修改來源照片。匯入照片採複製方式，批次改名則提供預覽、衝突阻擋與還原紀錄。

本 repository **不包含任何真實現場照片、清冊、資料庫、實際網路磁碟路徑、憑證或私鑰**。請勿將這些內容提交到 Git。

## 發行版

Windows 可執行檔請從 GitHub Releases 下載。Release binary 不直接提交進 Git 歷史。
GitHub Actions 會監聽 `v*` 標籤。建立正式版本前，`packaging/check_version_consistency.py` 會核對應用程式、套件、前端、TASKS 與發版文件的版本一致性；任一處不一致就停止 build／Release。版本確認通過後才可推送 Tag；以下是下一個 v1.11.0 開發版**未執行**的發版範例：

```powershell
git tag v1.11.0
git push origin v1.11.0
```

工作流程會在 `windows-latest` 上自動執行完整測試與 PyInstaller 打包、執行 `FireLens.exe --self-test`，接著建立 GitHub Release 並上傳：

- `FireLens-<版本>-windows-x64.exe`
- `FireLens-<版本>-setup.exe`
- `SHA256SUMS.txt`

如果 Tag 或任何受管版本來源不一致，Release 會直接停止，不會發布錯誤版本。

### 安全線上更新

FireLens v1.2.0 起內建 Windows 線上更新器。設定頁可手動檢查 GitHub Releases；有新版時會先下載到 `%LOCALAPPDATA%\\FireLens\\updates`，完成以下驗證後才允許安裝：

- Release 必須包含 `update-manifest.json` 與 `update-manifest.sig`
- manifest 必須通過 FireLens 內建 Ed25519 公鑰驗證
- EXE 檔名、版本、檔案大小與 SHA-256 必須完全符合已簽章 manifest
- 下載完成後先使用獨立暫存資料目錄執行新版 `--self-test`
- 安裝前備份目前 EXE；新版啟動失敗時更新程序會嘗試自動回滾

FireLens v1.6.0 起支援一鍵式安全更新：檢查到新版後只需按「下載並安裝」，程式會自動完成下載與上述安全驗證；全部通過後才會再詢問一次是否關閉、替換 EXE 並重新啟動。取消最終確認不會替換目前版本，已驗證的更新可在本次程式執行期間直接繼續安裝。

FireLens v1.6.1 起改用獨立 `FireLensUpdater.exe` 交易式更新：主程式會先取得 updater 的 transaction-bound `ready` 握手，確認更新器已真正啟動後才允許 FireLens 關閉；updater 等舊 EXE 解鎖、重新核對 SHA-256、備份並替換，再啟動新版。新版必須等 FastAPI／桌面視窗完成可用啟動、DOM ready 後回報 `healthy`，更新才算成功；新版 crash、`healthy` timeout 或替換失敗會自動嘗試 rollback 並重新啟動舊版。正式安裝版的 helper 由 setup 部署；portable/raw EXE 則從主 EXE 內嵌的受信任 payload 解出，並核對 build 時固定的 helper SHA-256。

若使用歷史 v1.5.0／v1.6.0 自動更新時發生「FireLens 關閉後沒有重新啟動，手動開啟仍是舊版」，請直接下載**最新版本的 `FireLens-<版本>-setup.exe` 覆蓋安裝**。不需要解除安裝、不需要刪除資料庫，也不要刪 `{app}\\data`；安裝／升級流程會保留 `{app}\\data\\firelens.sqlite3` 與使用者資料。

GitHub Actions 的簽章私鑰只可存放在 repository Actions Secret：

`FIRELENS_UPDATE_PRIVATE_KEY_B64`

私鑰不得提交到 Git。缺少此 Secret 時，Release workflow 會刻意失敗，避免發布 FireLens 無法驗證的未簽章更新。
